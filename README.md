# 現場スケッチ

「いいな」「うわっ」が来た瞬間の身体の一次データを一行で記録する練習帳。
読者は未来の自分だけ。詩を狙わない。下手なほど信用できる。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体（これ1枚で動く。HTML+CSS+JS内蔵） |
| `manifest.webmanifest` | PWA設定（ホーム画面追加時の名前・アイコン・全画面表示） |
| `sw.js` | service worker（オフラインでも開けるようにする） |
| `icon-192.png` / `icon-512.png` | ホーム画面用アイコン |

## 使い方（アプリ内）

1. 右上「設定」→ Anthropic APIキーを入力して保存（初回のみ。端末内にだけ保存される）
2. 現場と本文を書いて「書き留める」
3. 気が向いたら各付箋の「分けて仕分ける」／「まとめて仕分ける」→ 8種のハンコが押される
   （事実・身体・感情・思考・解釈・衝動・記憶・想像。種類が違うだけで、優劣はない）
   - 「分けて仕分ける」＝入力を文ごとに分けて判定する
   - 「まとめて仕分ける」＝分解せず、付箋全体を一つの流れとして判定する（ハンコは1つ）
   - 両方押せる。結果は別々に残るので、分けた場合とまとめた場合を並べて見比べられる
   - 各結果の右上「仕分けを消す」で取り消せる。消すとそのモードのボタンが戻り、仕分け直せる
4. 「全件を書き出す」→ 整形テキストがクリップボードにコピーされる（Notion貼り付け用）
5. 「控えを取る・戻す」→ 付箋と判定をそのままの形でファイルにする。端末を替えたときや、消えたときはここから戻す

一覧は、開いた直後は直近3件だけ出る。「これまでを見る」で全部出て、「たたむ」で戻る。
「現場」は直近に使った3つがボタンで出るので、1タップで入る。

判定は補助輪。書くだけで完結してよい。

## スマホのホーム画面から1タップで開く手順（GitHub Pages・推奨）

GitHub Pages に置くと、無料でHTTPS配信され、PWAとして全画面起動できる。

1. https://github.com にアクセスしてアカウントを作る（既にあれば不要）
2. 右上「+」→「New repository」
   - Repository name: `genba-sketchbook`（何でもよい）
   - **Private ではなく Public** を選ぶ（Pages無料枠はPublicのみ）
   - 「Create repository」
3. 「uploading an existing file」リンクをクリック → このフォルダの5ファイル
   （index.html / manifest.webmanifest / sw.js / icon-192.png / icon-512.png）を
   ドラッグ＆ドロップ → 「Commit changes」
4. リポジトリの「Settings」→ 左メニュー「Pages」
   - Branch: `main` / フォルダ: `/ (root)` を選んで「Save」
5. 1〜2分待つと `https://＜ユーザー名＞.github.io/genba-sketchbook/` が公開される
6. スマホのChromeでそのURLを開く → メニュー（⋮）→「ホーム画面に追加」
   → アイコンから1タップで全画面起動できるようになる

※ ソースコードは公開されるが、APIキーはコードに含まれず各端末のブラウザ内にしか保存されないので問題ない。

## ローカルで試す（PC）

`index.html` をダブルクリックするだけでも動く（file:// でもlocalStorage・API呼び出しは機能する。PWA機能のみ無効）。

## データについての注意

- 記録はブラウザのlocalStorageに保存される。**ブラウザのデータ消去やサイトデータ削除で消える**。
  - 戻せる形での退避は「控えを取る・戻す」→「ファイルにする」。これだけが復元できる。
  - 「全件を書き出す」は読み物としてNotionへ貼るためのもので、そこからは復元できない。
- 別の端末・別のブラウザとは同期しない（端末ごとに独立した帳面になる）。
- APIキーもlocalStorage保存。共用端末では設定しないこと。

## 判定機能の仕様メモ

- Anthropic Messages API を直接呼ぶ（`anthropic-dangerous-direct-browser-access: true` ヘッダー使用。個人利用前提）
- モデルは claude-sonnet-5 固定（2026-07-18あっちゃん決定。変更したいときは index.html の MODEL 定数を書き換える）
- 仕分けは8種。**種類に優劣はない**（点数化しない設計を、言葉ではなく構造で守る）。
  - その場にあったもの：**事実**（外界＝外受容）／**身体**（体内＝内受容）
  - あとから乗ったもの：**感情**（ラベル）／**思考**（流れた言葉。引用できる）／**解釈**（対象への意味づけ・評価）／**衝動**（行動への傾き）／**記憶**（過去へ）／**想像**（未来へ）
  - 通っている軸は「その場にあったもの／あとから乗ったもの」の一本だけ。表示は**実線／破線**で分け、色で序列をつけない（事実＝琥珀、身体＝赤、あとから乗ったもの6種＝すべて同じグレー破線）。
  - あとから乗ったものには質問形の補助質問が付く。記憶・想像は「いま体はどうなってる?」（先へではなく、**今へ戻す**）。
    ただし**その答えが同じ付箋の中にすでに書かれているときは問わず、どれがそれかを指す**（「直前に『頭に血が上る』がある」）。同じ問いも、同じ箇所への指し示しも、付箋の中で繰り返さない（二つ目以降は空でよい）。
    仕分け係は因果を推測しない（「〜から出てきた」を書かない）。因果を言うのは解釈であり、仕分けではない。文ごとに独立して判定するため、放っておくと既出の答えを訊いて問いが空振りする。
  - 分類の根拠：認知行動療法の思考記録（状況／自動思考／感情／身体反応）、内受容感覚と外受容感覚の区別、評価理論（解釈が感情を生む）、心的時間旅行（記憶と想像は同じ神経基盤の別方向。反芻と心配の区別に対応）、構成主義的感情理論（感情は身体感覚に言語ラベルを当てて構成される＝アプリの「時間の原則」と一致）。**臨床の道具ではなく観察の道具**として使う。
  - 「心の感覚」は身体に入れる（胸のざわつき・頭のパンパンは計器に映る）。「妄想」は想像に入れる（評価語を種類の名前に混ぜない）。
  - 想定外の値（空・モデルの誤出力）は `unknown`（破線・薄いグレー・「？」）で表示する。
- 判定の世代は `v`（`JUDGMENT_VERSION`）で見分ける。
  - `v:3` ＝ 8種。`v:2` ＝ 3値（写生／省略／解釈）。`v` なし ＝ さらに古い（映る／写生／映らない／一段降りろ）。
  - 古い判定は**名前をそのまま表示し、実線／破線だけ引き継ぐ**（写生＝実線、省略・解釈＝破線）。「写生」を事実と身体のどちらかに割り振ることはできないので、無理に読み替えない。
  - 3値だった時点に戻すなら `git checkout 42ad1b3 -- index.html sw.js`（ローカルタグ `three-verdicts` も同じ地点。このリポジトリはタグのpushを受け付けないため、コミットで指す）。
- 仕分けは2モード。共通の `SYSTEM_PROMPT` の末尾に、モードごとの分解ルール（`JUDGE_MODES`）を足して送る。
  - 結果はモードごとに `entry.judgments[mode]` に保存する。片方を実行しても、もう片方は消えない。
  - `entry.judgment`（単数）はモードの区別が無かった頃の旧形式。見出し「仕分けた」で表示し、消すこともできる。
- service worker は画面（HTML）をネットワーク優先で取る。2.5秒で応答が無いか圏外のときだけキャッシュを返す。
  更新のたびに `CACHE_NAME` を上げること（上げないと sw.js が変わらず、更新検出が走らない）。
- 控え（`控えを取る・戻す`）は JSON。`{"app":"genba-sketch","version":1,"exportedAt":...,"entries":[...]}`。
  取り込みは配列そのものも受ける。**今ある付箋は消さず、同じ id は重ねず、無いものだけ足す**（そのあと日付の新しい順に並べ直す）。
  「全件を書き出す」は読むための整形テキストで、そこからは復元できない。用途が違う。
- 一覧の初期表示は `RECENT_COUNT`（3件）まで。展開状態は保存しない（開くたびに畳んだ状態から始める）。
- 設定に「開いたらすぐ書ける」（本文へフォーカス）と「音声で書く」あり。
  音声は端末のブラウザの音声認識（`SpeechRecognition`）を使う。**実装によっては音声が外部へ送られる**ため、設定画面に明記している。非対応の端末ではボタンを出さない。
- 二行写生モード（外／内を分けて書く実験）は廃止した。8種の仕分けで「事実（外受容）／身体（内受容）」が
  **書いたあとに**同じ切り分けをするため、書く前に自分で分ける必要がなくなったから。
  現場では速く、判断は後で、という原則にも合う（二行モードは現場に判断を持ち込んでいた）。
  - 二行で保存済みの付箋（`entry.outer` / `entry.inner`）は、外／内のタグ付きでこれまで通り表示・書き出しできる。データは触っていない。
